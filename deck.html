Hand landmark detection

Combination of two more fundamental models

01 A palm detector finds hands and draws a box. It looks for palms rather than whole hands — a palm is a rigid blob, while fingers splay into a thousand shapes.
02 That crop, scaled to 192 or 224 pixels square, goes to the landmark model.
03 Out come 21 knuckle coordinates for the hand inside the box.
04 The next frame skips step one entirely — last frame's landmarks define this frame's crop. The detector only wakes up when tracking fails. This is how it stays performant.

21
points.

Every frame returns three things.

x, y Normalised image coordinates — 0 to 1 across the frame.
x, y, z World coordinates in metres, origin at the hand's centre.
L / R Handedness, with a confidence score.

The model finds the hand(s). It also measures coordinates. And quite literally nothing else.

Right hand · draw

Index extended, the rest curled.
Acts as the brush.

Left hand · size

Thumb and index pinch. The distance between the two tips sets brush width.

All of it runs in the browser.

Runtime MediaPipe ships to the web as one npm package - @mediapipe/tasks-vision. WASM package loads from a CDN and runs on the GPU inside the browser.
Model The runtime needs a model. A swappable .task file (a few MB) that Google hosts on a CDN. The browser fetches it once and caches it.
